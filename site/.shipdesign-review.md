## Findings ledger

| ID | Scope | Severity | Evidence | User impact | Required action |
|---|---|---|---|---|---|
| F-01 | responsive reflow | Major | At 390px, the hero lede extends beyond the viewport and is clipped on the right; the command preview also begins below the fold as a very tall block. | Mobile visitors lose part of the value proposition and must scroll through a disproportionate preview before reaching the story. | Constrain hero copy to the mobile shell, prevent horizontal clipping, and make the preview collapse into a compact, readable mobile composition. |
| F-02 | global composition | Major | Workflow, sources, principles, example, and install repeat a two-column heading/copy or heading/panel pattern. Three-plus consecutive sections become predictable in the full-page render. | The page loses narrative cadence and feels like a sequence of related templates instead of a progressing argument. | Preserve the visual direction but vary at least two macro compositions: give the workflow a stronger diagrammatic focal area and make the source explanation more integrated with the list. |
| F-03 | hierarchy/comprehension | Major | The Seven Sources section presents seven rows with stage labels, but the route from trigger to source family to quality gate is not visually summarized. | New users can name the sources but cannot quickly explain when each group is called or how ownership flows through the run. | Add a compact route legend or connected stage grouping that makes the seven-source sequence comprehensible before row-level reading. |
| F-04 | typography | Major | Secondary mono labels and descriptions render around 10–12px across the workflow, source rows, terminal metadata, and footer; at tablet/mobile they become difficult to scan. | Important context is functionally hidden behind refinement-sized type, especially in the workflow and source explanations. | Raise secondary text to a readable minimum, increase line-height where wrapped, and preserve mono only where it supports data or code. |
| F-05 | contrast | Major | Muted text such as hero lede, workflow annotations, source descriptions, and terminal metadata is visibly low contrast against dark, sage, and paper backgrounds. | Users with reduced contrast sensitivity may miss supporting explanation and route labels. | Increase muted text contrast while preserving the existing dark/paper/acid color system; verify representative text/background pairs. |
| F-06 | CTA/message duplication | Minor | Hero CTA, in-practice message, install heading, and footer all repeat the “give your agent better design” promise with limited progression. | The closing argument spends multiple sections restating the same value instead of moving from proof to action. | Make the in-practice section explicitly demonstrate the workflow output, and reserve the install section for the concrete next action and risk-reducing detail. |
| F-07 | interaction/accessibility | Minor | Navigation has visible focus styling, but the command preview is static despite presenting as a run; the mobile nav removes links without an alternate menu. | The hero implies a live process without state interaction, and mobile users have fewer direct section shortcuts. | Either clarify the preview as illustrative or add a lightweight state cue; ensure mobile navigation remains discoverable through the existing CTA/anchor structure. |
| F-08 | originality/finish | Minor | The page has a coherent editorial/terminal language, but repeated rectangular rows and equal grids dominate the long render. | The visual identity is credible but the most distinctive mechanism does not receive enough unique emphasis. | Use one signature visual treatment for source routing or the quality gate, keeping the existing palette and typography. |

## Landing-page audit answers

- Three consecutive sections repeat the same macro composition: **Yes**, especially after the workflow section.
- Strongest differentiator gets a signature visual moment: **Partially**. The command preview is strong, but source routing is not given an equally explanatory moment.
- Repeated CTAs/value claims progress the argument: **Partially**. The install CTA is clear; the in-practice and footer language repeats the promise.
- Secondary text readable at laptop and mobile sizes: **No**, see F-04.
- Contrast sufficient in muted text, tinted sections, terminal UI, and button states: **No**, see F-05.
- Core workflow/mechanism understandable from visual structure alone: **Partially**. The seven-step rail reads, but source ownership and route grouping require row-by-row reading.
- Mobile intentionally reflows the story: **No**, see F-01.
- Motion explains the product or decorates it: **Mostly decorates**. The staged reveal and cursor add atmosphere but do not change comprehension; see F-07.
